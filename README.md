# Truve

XRPL Credential 기반 가상자산 기부 인프라  
**Make crypto giving simple, verifiable, and tax-ready.**

한국 가상자산 보유자 600만 명, 그러나 가상자산 기부를 받을 수 있는 재단은 10곳 미만. 

Truve는 가상자산 기부를 보다 쉽고 편리하게 만들고, 기부자 확인(KYC)부터 기부 실행, 증빙 생성, 사후 검증까지 연결하는 XRPL 기반 가상자산 기부 인프라입니다. 

Trust & Give, Truve.
---

## 1. 한 줄 정의

Truve는 재단이 가상자산 기부를 받고, 기부자가 증빙까지 확인할 수 있게 돕는 XRPL 기반 기부 인프라입니다.

---

## 2. 핵심 가치 제안

Truve는 가상자산 기부를 단순 송금에서 끝내지 않고, 기부 이후의 증빙과 검증까지 연결합니다.

현재는 가상자산으로 기부하고 싶어도 어떤 재단이 받을 수 있는지 찾기 어렵고, 재단도 지갑만으로는 기부자 확인, 캠페인 구분, 원화 환산, 증빙 발급, 세무·감사 대응을 처리하기 어렵습니다.
Truve는 이 과정을 **재단/캠페인 탐색 → Xaman 결제 → Evidence Package 생성 → Donation Credential 발급·승인 → 기부현황 확인** 흐름으로 연결합니다.
기부금은 Truve가 보관하지 않고 기부자에서 재단으로 직접 이동하며, Truve는 해당 거래가 끝까지 설명 가능한 기록으로 남도록 돕습니다.

또한 Truve는 굿네이버스와 실제 활용 가능성을 논의하며, 재단이 가상자산 기부를 받을 때 필요한 운영 흐름을 MVP에 반영하고 있습니다. 
향후에는 이 구조를 재단 본부와 해외법인 간 송금·정산 기록까지 연결하는 B2B 기부 인프라로 확장하려고 합니다.

### 차별화 포인트

| 구분 | 현재 시장의 한계 | Truve 방식 | 차별화 포인트 |
| --- | --- | --- | --- |
| 기부 가능 재단 탐색 | 어떤 재단이 가상자산 기부를 받을 수 있는지 확인하기 어려움 | 재단, 추천 포트폴리오, 캠페인을 한 화면에서 탐색 | 기부 가능한 대상을 서비스 안에서 구조화 |
| 기부 실행 | 공식 수령 레일이 없거나 개별 문의·수기 안내에 의존 | Xaman 기반 XRPL 결제로 기부 실행 | 재단 직접 수령 구조는 유지하되 사용자 경험을 표준화 |
| 캠페인 관리 | 송금 거래만으로는 어떤 목적의 기부인지 구분하기 어려움 | 재단·캠페인·목표 모금액·진행률·지원 자산을 연결 | 목적형 모금 단위로 기부 관리 가능 |
| 증빙 생성 | 거래 해시, 캡처, 이메일, 엑셀 등으로 기록이 분산 | Evidence Package 생성 | 기부 이후 필요한 정보를 하나의 증빙 묶음으로 정리 |
| 검증 가능성 | 내부 DB나 수기 자료에 의존 | XRPL 기반 Donation Credential 발급·보유·검증 | 외부 검증자가 확인 가능한 구조 제공 |
| 세무·감사 대응 | 기부 시점 평가액, 거래 해시, 재단 승인 상태를 별도 확인 | 환산 참고값, Evidence, Credential 상태를 연결 | 세무법인·감사인의 검토 부담 감소 |
| 수익 구조 | 기부금 수수료 중심 모델은 기부자 부담으로 이어질 수 있음 | 재단 SaaS, 검증 콘솔, ESG/CSR 리포트 중심 B2B 모델 | 기부금 자체보다 운영 인프라에서 수익화 |

## 3. 주요 기능

### 3.1 재단·캠페인 탐색

기부자는 Truve에서 가상자산 기부가 가능한 재단, 추천 큐레이션, 목적형 캠페인을 확인할 수 있습니다.

### 3.2 Xaman 기반 가상자산 기부 결제

기부자는 Xaman 지갑을 통해 XRPL 기반 기부를 실행하고, 기부금은 재단으로 직접 전달됩니다.

### 3.3 Evidence Package 생성

거래 해시, 기부 시점, 기부 자산, 원화 환산 참고값, 재단·캠페인 정보를 묶어 증빙 자료로 정리합니다.

### 3.4 Donation Credential 발급 및 승인

기부 내역을 내부 DB 기록에만 남기지 않고, XRPL 기반 Donation Credential로 연결합니다.

### 3.5 내 기부 현황 대시보드

기부자는 총 기부액, 연결 지갑, Evidence, Donation Credential, 토큰 분포, 원화 환산 기준을 확인할 수 있습니다.

## 5. 비즈니스 모델

Truve의 수익 모델은 기부금에서 높은 수수료를 떼는 방식이 아니라, **재단과 검증기관이 사용하는 B2B 운영 인프라 과금 모델**입니다.

초기에는 재단 관리 SaaS, 세무·감사 검증 콘솔, ESG/CSR 리포트로 수익을 만들고, 중장기적으로는 국제 기부재단의 해외법인 간 송금·정산 인프라로 확장합니다. 이 구조는 기부자 부담을 줄이면서도 재단의 실제 운영 비용과 정산 업무를 줄이는 방향입니다.

### 5.1 수익 구조

| 수익원 | 과금 방식 | 예시 단가 | 제공 가치 |
| --- | --- | --- | --- |
| 재단 관리 SaaS | 월 구독료 | 기관당 월 50만~150만원 | 기부 수령 관리, 캠페인별 내역, 원화 환산 참고값, Evidence/Credential 상태 관리 |
| 검증 콘솔 | 월 구독료 | 법인당 월 100만~300만원 | 거래 해시 검증, 기부 시점 평가액 확인, 재단 승인 상태 확인, Donation Credential 검증 |
| ESG/CSR 리포트 | 건별 과금 | 리포트당 10만~30만원 | 기업 기부 내역, Proof Link, 감사·IR용 증빙 패키지 |
| 온보딩/세팅 | 초기 구축비 | 기관당 200만~500만원 | 재단 지갑 연동, 캠페인 세팅, 내부 운영 플로우 구축 |
| API 사용료 | 사용량 기반 과금 | API 호출량 또는 월 기본료 | Evidence 생성, Credential 상태 조회, Proof Link 생성, 캠페인 현황 조회 |

## 6. 문제 정의

현재 가상자산 기부가 활성화되지 않는 가장 큰 이유는 기부 수요 부족이 아니라, **기부 이후까지 이어지는 운영 구조가 충분히 마련되어 있지 않기 때문입니다.**

기부자는 어떤 재단이 가상자산 기부를 받을 수 있는지 찾기 어렵습니다. 기부 시점의 원화 가치, 세무 참고 지표, 영수증 발급 가능성, 증빙 보관 상태도 따로 확인해야 합니다.

재단도 지갑 주소만 준비한다고 가상자산 기부를 안정적으로 운영할 수 없습니다. 기부자 확인, 수령 자산 기준, 캠페인별 기부금 구분, 환산 기준, 증빙 관리, 세무·감사 대응까지 함께 처리할 수 있는 운영 인프라가 필요합니다.

특히 국제 NGO나 해외사업을 운영하는 재단은 본부와 해외법인 간 자금 이동, 캠페인별 배분, 정산 자료 관리까지 함께 처리해야 합니다. 이 과정이 분리되어 있으면 회계·감사 대응이 복잡해지고, 기부금이 어떤 사업에 어떻게 연결되었는지 설명하기 어려워집니다.

Truve는 이 문제를 단순 결제 문제가 아니라 **가상자산 기부의 운영·증빙·검증·정산 구조가 부족한 문제**로 봅니다.

---

## 7. 문제의 규모 / 심각성

국내 가상자산 시장은 이미 대중화 단계에 들어섰습니다. 금융위원회가 2026년 3월 25일 발표한 2025년 하반기 가상자산사업자 실태조사에 따르면, 2025년 말 기준 국내 거래가능 이용자 계정 수는 1,113만 개, 원화예치금은 8.1조 원, 2025년 하반기 일평균 거래규모는 5.4조 원입니다.

반면 기부 영역에서는 가상자산 보유자, 재단, 세무 검증 주체가 함께 사용할 수 있는 표준 운영 방식이 아직 충분히 자리 잡지 못했습니다. 시장에는 가상자산 보유 기반이 존재하지만, 재단 입장에서는 수령 이후의 평가·정산·증빙·감사 대응 부담이 남아 있습니다.

Truve는 이 간극을 기회로 보고, 가상자산 기부가 실제 재단 운영과 해외사업 정산까지 이어질 수 있는 인프라를 만들고자 합니다.

## 8. 기존 솔루션의 한계

현재 시장은 공식 가상자산 기부 레일이 부족하고, 일부 경우에만 개별 문의·지갑 주소 전달·수기 확인으로 대응할 수 있는 상태입니다.

| 기존 접근 | 장점 | 한계 |
| --- | --- | --- |
| 개별 문의 후 수기 안내 | 빠르게 대응 가능 | 공식 기부 레일로 확장하기 어렵고, 담당자 의존도가 높음 |
| 재단 지갑 주소 전달 | 기술적으로는 송금 가능 | 기부자 확인, 캠페인 매핑, 환산 기준, 증빙 발급이 별도로 필요 |
| 블록체인 익스플로러 조회 | 거래 해시 확인 가능 | 해당 거래가 어떤 기부자·재단·캠페인·증빙과 연결되는지 설명하기 어려움 |
| 수기 엑셀 관리 | 기존 재단 운영 방식과 유사 | 거래량 증가 시 누락·오류·검토 지연 가능성 증가 |
| 일반 기부 플랫폼 | 사용자 경험이 익숙함 | 가상자산 트랜잭션, 온체인 Credential, 외부 검증 구조와 직접 연결되지 않음 |
| 내부 DB 기반 증빙 | 구현이 비교적 쉬움 | 외부 검증자가 동일 기준으로 확인하기 어렵고, 감사 자료로 재가공 필요 |
| 기존 해외송금 정산 방식 | 제도권 안정성 보유 | 송금, 환전 캠페인별 배분, 증빙 자료가 분리되어 사후 정리 부담이 큼 |

## 9. 프로젝트 접근 차별성

Truve는 기부를 **결제 완료**에서 끝내지 않습니다. 기부가 완료된 뒤 필요한 데이터를 구조화하고, Evidence Package와 Donation Credential로 연결합니다.

Truve는 **굿네이버스와 실제 활용 가능성을 논의**하며, 재단이 가상자산 기부를 받을 때 필요한 운영 흐름을 MVP에 반영하고 있습니다. 이를 통해 단순 기술 데모가 아니라, 실제 재단이 고민하는 기부 수령, 캠페인 관리, 증빙 발급, 세무·감사 대응 문제를 반영한 구조로 발전시키고 있습니다.

또한 Truve는 초기에는 가상자산 기부의 수령·증빙 문제를 해결하고, 향후에는 재단 본부와 해외법인 간 송금·정산 기록까지 연결하는 B2B 기부 인프라로 확장하려고 합니다.

## 10. Why XRPL

Truve가 XRPL을 선택한 이유는 **결제, 기록, 증빙을 하나의 흐름으로 연결하기 좋기 때문**입니다.

XRPL은 빠른 결제 처리, 낮은 트랜잭션 비용, DestinationTag·Memo 기반 기록 연결, Credential 구조를 제공합니다. Truve는 이를 활용해 기부자가 재단에 직접 송금한 거래를 Evidence Package와 Donation Credential로 연결합니다.

| XRPL 요소 | Truve에서의 역할 | 적용 의미 |
| --- | --- | --- |
| Payment | 기부자에서 재단으로 스테이블코인 직접 송금 | Truve가 기부금을 보관하지 않는 구조에 적합 |
| TrustLine | 재단이 수령 가능한 자산 관리 | RLUSD, USDC 등 지원 자산별 수령 정책 관리 가능 |
| DestinationTag | 캠페인 또는 목적별 기부금 구분 | 하나의 재단 지갑 안에서도 캠페인 단위 매핑 가능 |
| Memo | `receipt_id`, `evidence_hash`, `compliance_hash` 등 기록 | 오프체인 Evidence와 온체인 거래를 연결하는 단서 제공 |
| XLS-70 Credential | 기부 사실의 발급·보유·검증 | 기부를 단순 거래가 아니라 검증 가능한 증빙으로 확장 |

XRPL의 ledger는 일반적으로 약 3~5초 단위로 닫히며, 표준 트랜잭션의 최소 비용은 0.00001 XRP로 안내되어 있습니다. 이 특성은 소액·반복 기부, 빠른 결제 확인, 낮은 수수료가 중요한 기부 인프라와 잘 맞습니다.

또한 DestinationTag와 Memo를 활용하면 캠페인 ID, 영수증 ID, Evidence 해시, 정산 ID 등을 온체인 거래와 연결할 수 있습니다. Truve는 이 구조를 활용해 기부 증빙뿐 아니라 향후 해외법인 송금·정산 기록까지 확장하려고 합니다.

Truve에서는 이를 캠페인 식별, 영수증 ID, Evidence 해시, 검증 참조값과 연결하는 방식으로 활용할 수 있습니다.

## 13. XRPL Credential 구조

Truve의 핵심은 기부 내역을 단순 DB 기록이 아니라 **검증 가능한 Donation Credential**로 바꾸는 것입니다.

| 역할 | 설명 |
| --- | --- |
| 재단 | Credential 발급자 |
| 기부자 | Credential 보유자 |
| 세무법인·감사인 | Credential 검증자 |
| Truve | 기부·증빙·검증 인프라 제공자 |

기부금은 Truve를 거치지 않고 재단으로 직접 전달됩니다. Truve는 해당 거래를 기반으로 Evidence Package를 생성하고, 재단은 이를 Donation Credential로 발급합니다.

기부자는 Xaman에서 Credential을 승인하고, 이후 내 기부 현황에서 해당 Credential 상태를 확인할 수 있습니다. 이 구조를 통해 기부는 단순 결제 완료 상태가 아니라, 이후에도 설명 가능한 증빙 상태로 남습니다.

## 14. 내 기부 현황

내 기부 현황 페이지는 기부자가 자신의 기부 데이터를 확인하는 포트폴리오 화면입니다.

현재 구현 기준으로 다음 정보를 제공합니다.

| 항목 | 설명 |
| --- | --- |
| 총 기부액 | 사용자의 누적 기부 금액 |
| Donation Summary | Day / Week / Month / YTD / Total 기준 기부 흐름 |
| 연결 지갑 정보 | Xaman 등 연결 지갑 상태 |
| DB/로컬 기록 동기화 상태 | 실제 기록과 임시 기록의 동기화 확인 |
| Recent Evidence | 최근 생성된 Evidence Package |
| Donation Credentials | 발급·승인된 Credential 목록 |

이 페이지는 단순히 얼마를 기부했는지를 보여주는 화면이 아니라, **결제·Evidence·Credential 상태가 실제로 연결되어 있는지를 사용자가 확인하는 신뢰 대시보드**입니다.

## 15. 굿네이버스 협업 반영 방향

Truve는 굿네이버스와 실제 활용 가능성을 논의하며, 재단이 가상자산 기부를 받을 때 필요한 운영 흐름을 함께 검토하고 있습니다.

이를 통해 Truve는 단순히 블록체인 기부 기능을 보여주는 데서 끝나지 않고, 실제 재단이 필요로 하는 기부 수령, 캠페인 관리, 증빙 발급, 세무·감사 대응 흐름을 MVP에 반영하고 있습니다.

향후에는 이 구조를 국제 NGO와 재단의 본부-해외법인 간 송금·정산 기록까지 연결하는 B2B 인프라로 확장하려고 합니다.

## 19. 최종 목표

Truve의 목표는 또 하나의 기부 플랫폼을 만드는 것이 아닙니다.

기부자는 더 쉽게 가상자산으로 기부하고, 재단은 더 안정적으로 기부를 운영하며, 나아가 국제 기부 재단의 해외법인 간 송금·정산까지 관리할 수 있는 기부·정산 인프라로 확장하는 것입니다.

**Truve는 기부 증빙 인프라**에서 출발해, 기부 재단의 해외법인 송금·정산까지 연결하는 운영 인프라로 확장하려고 합니다.
